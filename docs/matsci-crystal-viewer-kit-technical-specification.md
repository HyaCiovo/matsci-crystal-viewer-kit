## 二、软件功能简介

### 2.1 软件概述

Matsci Crystal Viewer Kit 是面向材料科学、晶体学和计算材料学场景的浏览器端三维晶体结构可视化组件库。软件接收经过标准化的晶体结构场景 JSON，将原子、化学键、晶胞、坐标轴、表面、多面体、箭头、线段及文本标签等结构对象转换为 Three.js 场景，并通过 WebGL 在浏览器画布中完成三维渲染。

软件以 React 组件形式对外提供能力，能够嵌入材料数据库、材料详情、对话式材料分析、工作流节点和结构结果展示等业务页面。组件库将数据适配、场景构建、交互拾取、相机控制、资源生命周期和展示设置进行模块化封装，使上层业务无需直接管理 Three.js 场景对象和 WebGL 资源。

### 2.2 主要功能

1. **晶体结构三维展示**：展示原子、化学键、晶胞边界、坐标轴、表面、凸包、多面体、箭头和线段等结构对象。
2. **多种结构表达方式**：支持由结构场景 JSON 描述的静态结构、分组结构、分层结构和带可见性控制的复合场景。
3. **三维视图交互**：支持旋转、缩放、平移、视角复位、相机状态同步和正交相机展示。
4. **结构对象选择**：支持原子或其他可交互对象的点击、多选、选中轮廓和选中状态恢复。
5. **悬停提示**：支持指针移动检测、对象悬停识别、tooltip 展示和光标状态切换。
6. **结构显示控制**：支持按对象名称或对象类别切换原子、化学键、晶胞、多面体等结构元素的显示状态。
7. **原子和键参数调整**：支持原子半径、化学键半径、球体分段等展示参数配置，并通过提交式更新避免拖动过程中的重复重建。
8. **标签与坐标轴展示**：支持 CSS2D 文本标签、标签数量限制、坐标轴小窗及主视口恢复。
9. **主题和预览适配**：支持亮色和暗色主题、材料数据库预览布局、局部展示设置及不同画布尺寸。
10. **场景放大与导出**：提供结构视图放大、还原、相机状态处理，以及图片、DAE、GLTF、GLB、USDZ 等导出入口。
11. **动画结构展示**：提供普通动画场景和声子动画场景组件，用于展示结构随时间或振动模式变化的结果。
12. **宿主集成保护**：支持宿主应用通过懒加载、`Suspense` 和局部错误边界加载三维组件，确保结构加载或 WebGL 初始化失败时不影响页面其他业务区域。
13. **性能观测**：提供 Storybook 性能基准页面，用于观察构建耗时、帧间隔、绘制调用、GPU 几何体、三角形数量和高频悬停拾取次数。

### 2.3 典型使用流程

1. 后端接收 CIF、POSCAR 或其他晶体结构文件并完成结构解析、标准化和场景 JSON 生成。
2. 前端应用获取场景 JSON 或结构资源引用，并将其传递给 Crystal Viewer Kit。
3. React 场景组件根据数据和展示参数创建或更新场景管理器。
4. 场景管理器构建 Three.js 场景、相机、控制器、WebGL 渲染器和 CSS2D 标签渲染器。
5. 用户在画布中旋转、缩放、选择、悬停或切换结构类别，组件执行局部交互和增量更新。
6. 页面关闭、路由切换、场景替换或组件卸载时，组件释放事件、画布、标签、几何体、材质和 WebGL 资源。

## 三、技术特点

### 3.1 组件化和分层设计

软件采用 React 组件层、场景生命周期层、Three.js 构建层和宿主适配层的分层结构。React 层负责组件属性、控制条、加载状态和错误边界；场景层负责相机、渲染、resize、交互和销毁；构建层负责 JSON 图元解析、几何体、材质和实例化资源；宿主适配层负责数据接入、展示设置、懒加载和业务容错。

这种分层方式将业务状态变化与底层 WebGL 资源变化隔离，使页面上与场景拓扑无关的 React 更新不会自动触发完整场景重建。

### 3.2 基于场景 JSON 的统一数据驱动

软件以场景 JSON 作为前后端之间的结构展示协议。JSON 中的分组、对象名称、图元类型、位置、尺寸、颜色、可见性和交互属性经过解析后形成统一的 Three.js 场景树。前端主要负责展示和交互，复杂晶胞规范化、成键算法和结构结果一致性保留在后端权威路径。

### 3.3 WebGL 与 Three.js 三维渲染

软件使用 Three.js 管理相机、场景、几何体、材质、光照、控制器、raycast 和渲染器，通过 WebGL 完成三维结构绘制。对坐标轴小窗采用 scissor 和 viewport 局部绘制，并在完成小窗绘制后恢复主视口状态。

### 3.4 实例化渲染与资源复用

对于同形状、同材质且位置数组结构一致的原子集合，软件优先合并为 `THREE.InstancedMesh`，使用实例矩阵描述每个原子的平移、旋转和缩放。需要点击或 tooltip 的批量球体通过 Three.js 的 `instanceId` 映射回原子数据，并使用实例颜色完成单原子悬浮高亮；带动画、hoverLabel 或其他不适合批处理语义的对象继续回退到普通 Mesh。球体、圆柱、箭头头部和立方体等重复资源按参数生成缓存，减少重复创建顶点缓冲和材质对象。

### 3.5 高频交互合帧

软件使用 `requestAnimationFrame` 合并连续指针事件，在一个动画帧内只保留最新指针坐标并执行一次 hover raycast。一次交集结果同时用于 tooltip、cursor 和悬停重绘判断，避免同一事件链中重复执行命中检测。

### 3.6 增量更新与稳定依赖

软件将静态场景拓扑、对象索引、可见性状态和交互回调分离。React 回调通过稳定引用更新，材料预览设置使用 memo，元素显示开关使用对象名索引，半径滑块采用 draft/applied 双状态。只有真正影响场景拓扑或几何参数的变化才触发重建。

### 3.7 生命周期和内存安全

软件对场景替换、组件销毁、路由切换、放大还原和重复打开等路径执行资源管理。旧场景递归释放非共享几何体、材质和贴图；共享缓存资源在 viewer 最终销毁时统一释放；销毁时同步移除事件监听、取消 pending `requestAnimationFrame`、移除 DOM 渲染器并释放 WebGL 上下文。

### 3.8 面向宿主的容错和展示适配

组件不绑定具体业务页面、请求库或缓存实现，宿主可以通过懒加载和局部错误边界隔离三维区域异常，并自行决定结构数据的请求和缓存策略。组件提供稳定画布比例、DPR 上限和标签预算，在显示质量、内存占用和交互可用性之间进行平衡。

## 四、创新点

以下创新点仅描述本组件库及其宿主适配能力形成的工程实现增量，不将上游 Crystal Toolkit 或 `matsci-ui` 已有的基础结构模型直接表述为本项目独创。

### 4.1 交互实例化与精确命中映射

软件将批量渲染和逐原子交互解耦：同一球体对象中的多个原子仍使用一个 `InstancedMesh`，raycast 命中后通过 `instanceId` 定位原子索引，再映射到原有 JSON、点击回调和 tooltip。悬浮高亮只更新命中的实例颜色，离开时恢复该实例的基础颜色，不会把整批原子一起变色。带动画、hoverLabel、异构几何或其他不适合实例化的对象保留普通 Mesh 回退路径。

### 4.2 单帧单次悬停拾取机制

软件将连续 `mousemove` 事件聚合到下一次动画帧，仅执行一次 hover raycast，并复用交集结果完成 tooltip 和光标判断。该机制降低高频指针输入对 CPU、raycast 和 React 状态更新的压力，同时保持点击拾取的独立精度。

### 4.3 共享资源安全回收机制

软件为场景替换和 viewer 最终销毁区分资源所有权：场景替换阶段仅释放非共享资源，缓存资源继续供新场景复用；viewer 销毁阶段再由 `ThreeBuilder.dispose()` 释放缓存。该机制兼顾场景反复切换时的资源安全和构建性能，减少 GPU 几何体、材质和贴图长期残留的风险。

### 4.4 面向结构展示的更新边界控制

软件将结构 JSON、场景拓扑、对象索引、可见性、回调和展示参数拆分为不同更新边界。类别开关通过索引执行增量可见性更新，滑块通过提交策略延后重建，回调变化不重新构建场景，从而减少画布频繁更新和重复分配。

### 4.5 三维组件的局部故障隔离

软件在业务应用中将三维展示封装在独立的懒加载和错误边界内。结构 JSON 异常、WebGL 初始化失败、三维模块加载失败等问题只影响结构预览区域，材料详情、对话或工作流页面仍可继续使用，适合复杂业务系统中的渐进式增强。

### 4.6 可复现的性能观测闭环

软件提供交互式基准页面，将场景构建耗时、帧间隔、P95、draw calls、GPU geometry、三角形数量和 hover 拾取次数纳入同一观测入口。优化结果不依赖主观观感，而是可以在固定设备、固定参数和固定采样方法下进行回归比较。

## 五、软件总体架构和技术路线

### 5.1 总体架构

```text
晶体结构文件（CIF/POSCAR 等）
        |
        v
后端结构解析、标准化、成键和场景 JSON 生成
        |
        v
宿主应用查询、缓存、懒加载和安全集成层
        |
        v
React 晶体场景组件
        |
        v
Scene 场景生命周期管理器
        |------------------|-------------------|------------------|
        v                  v                   v                  v
ThreeBuilder        SceneObjectRegistry  SceneInteraction   WebGL/CSS2D
图元构建与缓存      对象和可见性索引     rAF 合帧拾取       主视图和标签
```

### 5.2 数据处理流程

1. **输入阶段**：后端接收结构文件，完成解析和必要的结构规范化。
2. **传输阶段**：后端返回规范化 scene JSON 或可寻址的结构资源引用，前端避免无必要的重复中转。
3. **适配阶段**：宿主适配层对查询结果、主题和业务显示设置进行校验与转换。
4. **构建阶段**：Scene Graph 递归读取 JSON 内容，ThreeBuilder 创建或复用几何体、材质和图元。
5. **渲染阶段**：Scene 使用 WebGLRenderer 和 CSS2DRenderer 绘制主视图、标签及坐标轴小窗。
6. **交互阶段**：用户输入由控制器、对象索引和 rAF 拾取机制处理，必要时只更新局部状态。
7. **销毁阶段**：场景替换或组件卸载时按所有权释放 Three.js 和 DOM 资源。

### 7.2 核心模块详细说明

#### 7.2.1 场景生命周期模块

该模块负责创建和管理 WebGLRenderer、相机、控制器、CSS2DRenderer、场景根节点、坐标轴小窗和事件监听。模块将窗口 resize、ResizeObserver、容器变化和放大还原请求统一调度到下一帧执行，同一动画帧内只执行一次真实 resize。组件销毁时取消 pending rAF，移除事件，销毁控制器和辅助渲染器，并释放场景资源。

#### 7.2.2 ThreeBuilder 几何体和材质模块

该模块根据图元类型创建球体、圆柱、线、面、箭头、多面体和文本等对象。对重复参数建立缓存键，对共享几何体和材质进行复用；对满足条件的静态原子组创建 InstancedMesh；在 viewer 最终销毁时统一释放缓存资源。模块同时维护资源共享标记，避免场景替换时误释放仍被新场景使用的资源。

#### 7.2.3 交互拾取模块

该模块使用 Three.js Raycaster 判断指针位置对应的对象。hover 事件通过 requestAnimationFrame 合并，保存同帧最新坐标，每帧最多执行一次 hover raycast。命中普通 Mesh 时沿父节点查找注册对象，命中 `InstancedMesh` 时额外携带 `instanceId`，由注册表将实例映射回原子 JSON。点击路径保留 clickable 对象集合，兼容批量实例和普通 Mesh 两种对象，以保证点击选择、选中轮廓和点击回调的准确性。

#### 7.2.4 对象索引和可见性模块

该模块在场景构建完成后建立对象名称到 Object3D 的 Map，并按原子、化学键、晶胞和多面体等类别保留轻量索引。显示开关直接通过索引定位对象，避免反复遍历完整场景树；这类操作不改变场景拓扑，不触发完整重建。

#### 7.2.5 React 集成模块

该模块将底层 viewer 封装为 React 组件，管理加载、错误、放大、还原、属性设置、主题、导出和用户回调。组件使用稳定 settings、回调 ref 和按需更新边界，减少父级页面状态变化造成的场景重建。

#### 7.2.6 宿主适配和容错模块

该模块为宿主应用提供稳定的组件边界、主题和设置注入点，并允许宿主使用懒加载、Suspense 和局部错误边界隔离三维区域。组件接收规范化 scene JSON，不内置特定业务请求库或查询缓存；宿主可以根据业务需要复用结构数据。该边界减少组件库与具体页面、路由和后端 API 的耦合。

## 九、相对于参考组件的工程优势

参考对象为 `matsci-ui` 项目中的 MP 衍生晶体预览组件。以下对比仅用于说明本软件的改造和二次开发内容，不改变上游代码和许可证的归属。

| 对比维度 | 参考实现/基础能力 | 本软件的工程增强 |
| --- | --- | --- |
| 使用方式 | 晶体预览功能与应用页面耦合度较高 | 抽取为可复用的独立 React 组件库 |
| 场景更新 | 场景属性变化可能进入完整构建路径 | 拆分拓扑、索引、可见性和回调更新边界 |
| 原子批处理 | 以逐对象展示为主 | 对满足条件的静态原子使用 InstancedMesh |

| 资源生命周期 | 场景移除与资源回收边界较粗 | 区分共享资源和场景资源，替换与销毁分开回收 |

## 十、软件质量和回归要求

### 10.1 功能回归项目

1. 打开真实材料详情，检查原子、化学键、晶胞、坐标轴小窗、标签和主题显示。
2. 旋转、缩放、平移和复位视角，确认画布尺寸变化后结构比例正常。
3. 点击和悬停原子，确认 tooltip、cursor、选中轮廓和回调行为正常。
4. 切换 atoms、bonds、unit cell、polyhedra 等显示开关，确认执行增量可见性更新。
5. 连续拖动原子半径和键半径，确认提交前不重复重建，提交后显示结果正确。
6. 重复打开、关闭、放大、还原、刷新和路由切换结构预览，确认事件、canvas、标签和 GPU 资源不持续累积。
7. 在模型选择器和其他浮层场景中检查弹层不会被父级容器裁剪。

### 10.2 性能回归观察目标

| 场景 | 观察指标 | 建议目标 |
| --- | --- | --- |
| 10,000 个非交互原子 | draw calls | 在相同 InstancedMesh 条件下保持 1 个实例批次 |
| 10,000 个非交互原子 | GPU geometry | 在不新增其他图元时保持 1 |
| 连续 burst hover | raycast | 每个动画帧最多 1 次 |

| 连续 resize | 实际 resize 执行 | 同一帧最多 1 次 |

## 十二、依赖发布和构建说明

组件库当前发布到团队私有 npm registry 的固定版本：

```json
"@gnosys/matsci-crystal-viewer-kit": "0.1.6"
```

当前版本包含组件库构建后发布的 `dist/index.js`、`dist/index.d.ts` 和 `dist/style.css`。修改组件库 `src` 后，应先执行检查、构建并递增版本：

```bash
cd matsci-crystal-viewer-kit
pnpm typecheck
pnpm test
pnpm build
pnpm release:prepare patch
pnpm release:publish
```

宿主应用更新依赖版本并重新安装：

```bash
pnpm add @gnosys/matsci-crystal-viewer-kit@<new-version> --save-exact
pnpm install
```

这样宿主应用和组件库之间具有明确的版本边界，避免宿主在未完成发布校验时直接消费未发布的构建产物。

## 十三、后续改进方向

1. 对超过当前实例化预览能力且需要逐原子交互的超大结构，可评估 GPU picking、空间索引和分块 LOD。
2. 对 GLTF、USDC 等较少使用的导出器继续采用按需加载，降低首屏 bundle 成本。
3. 后端可提供带内容哈希和版本号的紧凑 scene DTO、ETag 及结构转换缓存，减少重复 CIF 解析和重复传输。
4. 对长时间动画、复杂表面计算或重型解析，可评估 Web Worker 和 OffscreenCanvas；引入前应验证主线程交互、CSS2D 标签和错误恢复复杂度。
5. 如需形成正式跨设备性能结论，应建立统一浏览器版本、画布尺寸、材料结构集、DPR、采样次数和内存采样工具，并分别采集 CPU、JS heap、GPU 资源和网络指标。
